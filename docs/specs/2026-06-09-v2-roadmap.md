### Tier 3 — live data wiring
Currently all data is sample. To go live:
1. **Supabase reads** — set `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY` in Vercel, then update `getSupabase()` consumers in:
   - /sources → query `sources` table for real catalog rows
   - /properties → query `data_records` filtered by `family='portfolio'`
   - /signals → query `v_latest_source_data` view
2. **Reprime /api/search proxy** — already wired via `lib/reprime-api.ts`; needs a UI surface (/explore page)
3. **Reprime /api/health polling** — client island on /signals that hydrates the status dots every 30s
4. **FRED/Treasury live data** — direct client-side fetch (no key needed for some endpoints) for the ticker

## Important constraints (carry forward)
- **Honesty rule**: every visible number is live-bound OR carries a `Sample` badge. No fabricated `LIVE` labels.
- **No frontend framework rewrites without ADR** (per Reprime CLAUDE.md ADR-001 — Reprime stays vanilla JS; Atlas is a SEPARATE Next.js app)
- **No secrets in source** — Vercel env + GH Actions secrets only
- **prefers-reduced-motion** — every animation must respect it

## Cost reality (from this session)
